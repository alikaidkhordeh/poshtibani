# راهنمای ساده‌ی نصب چت پشتیبانی (ننه پت) روی سرور

همه‌چیز داخل یک پوشه‌ی جدا روی سرور نصب می‌شود: `~/chat-poshtibani`
نصب هیچ چیزی را پاک نمی‌کند و به ربات‌ها، پنل نوبتی (`~/panel-nobatdehi`)، nginx و پوشه‌های دیگر سرور
دست نمی‌زند.

**هیچ پورتی لازم نیست باز شود.** چت از راه «تونل Cloudflare» به اینترنت وصل می‌شود: خود سرور به
Cloudflare وصل می‌شود، نه برعکس. پس پورت‌های ۸۰ و ۴۴۳ (و هر پورت دیگری) همان‌طور که هست برای
برنامه‌های دیگر می‌ماند و لازم نیست آزاد بودن پورتی را بررسی کنید. آخر نصب، خود نصب‌کننده بررسی
می‌کند که تونل وصل شده باشد.

**یک لینک کافی است** (همان ساب‌دامینی که ساختید):

- صفحه‌ی چت برای مراجعه‌کننده‌ها: `https://chat.enetvip.com`
- پنل مدیریت (برای شما و پشتیبان‌ها): `https://chat.enetvip.com/admin`

## کدها کجا می‌مانند؟

- گیت‌هاب فقط «انبار» کد است. موقع نصب، یک نسخه‌ی کامل از کدها روی سرور کپی می‌شود
  (`~/chat-poshtibani/app`) و چت از روی همان اجرا می‌شود. بعد از نصب، چت به گیت‌هاب نیازی ندارد.
- اطلاعات (گفتگوها، اسم و شماره‌ی مراجعه‌کننده‌ها، دیتابیس ربات، تنظیمات) فقط روی سرور شماست:
  `~/chat-poshtibani/data`
- هر بار که کد جدید گرفته شود، نسخه‌ی قبلی به اسم `app.old-...` کنار آن نگه داشته می‌شود.

## قدم ۱: بررسی Docker (فقط نگاه می‌کند)

```bash
docker --version && docker compose version
```

اگر هر دو نسخه را نشان داد، آماده است.
اگر Docker نبود، روی این سرور که برنامه‌های دیگر هم دارد چیزی نصب نکنید و اول هماهنگ کنید؛
نصب‌کننده هم خودش هیچ چیزی نصب نمی‌کند.

## قدم ۲: کلید موقت گیت‌هاب (فقط برای نصب و به‌روزرسانی)

کلید فقط اجازه‌ی **خواندن** همین یک پروژه را می‌دهد. وقتی تاریخش تمام شود فقط خود کلید از کار
می‌افتد؛ هیچ کد و اطلاعاتی پاک نمی‌شود و چت مثل قبل کار می‌کند.

1. این صفحه را باز کنید: https://github.com/settings/personal-access-tokens/new
2. **Token name**: `chat-server`   **Expiration**: `7 days`
3. **Repository access**: **Only select repositories** و از لیست `poshtibani`
4. **Repository permissions** ← **Contents** ← **Read-only**
5. **Generate token** و کلیدی که با `github_pat_` شروع می‌شود را کپی کنید.

## قدم ۳: Cloudflare

رکورد `chat.enetvip.com` را قبلاً ساخته‌اید؛ کار دیگری در سایت Cloudflare لازم نیست.
روش تونل رکورد مخصوص خودش را لازم دارد، پس نصب‌کننده **فقط همین یک رکورد** (`chat.enetvip.com`) را با
رکورد تونل جایگزین می‌کند. به هیچ رکورد دیگری از دامنه دست نمی‌زند.

## قدم ۴: نصب (یک دستور)

با SSH (مثلاً MobaXterm) وارد سرور شوید و این را بزنید:

```bash
mkdir -p ~/chat-poshtibani && cd ~/chat-poshtibani && read -rsp "GitHub token: " GH_TOKEN && echo && curl -fsSL -H @<(printf 'Authorization: Bearer %s\n' "$GH_TOKEN") -H "Accept: application/vnd.github.raw" -o install.sh "https://api.github.com/repos/alikaidkhordeh/poshtibani/contents/deploy/install.sh" && CHAT_GITHUB_TOKEN="$GH_TOKEN" CHAT_HOST=chat.enetvip.com CHAT_DNS_OVERWRITE=1 bash install.sh
```

1. کلید گیت‌هاب را بچسبانید (در MobaXterm: کلیک راست) و Enter بزنید. موقع چسباندن چیزی دیده
   نمی‌شود؛ عادی است.
2. **فقط بار اول:** یک لینک Cloudflare نشان داده می‌شود. آن را کپی کنید (در MobaXterm همین که با موس
   انتخابش کنید کپی می‌شود) و در مرورگری باز کنید که وارد حساب Cloudflare هستید. دامنه‌ی
   `enetvip.com` را انتخاب کنید و **Authorize** بزنید. بعد به ترمینال برگردید؛ خودش ادامه می‌دهد.
3. نصب‌کننده رکورد `chat.enetvip.com` را به تونل وصل می‌کند و چت را می‌سازد. بار اول چند دقیقه طول
   می‌کشد.
4. در پایان این‌ها نمایش داده می‌شود:
   - لینک صفحه‌ی چت: `https://chat.enetvip.com`
   - لینک پنل مدیریت: `https://chat.enetvip.com/admin`
   - نام کاربری مالک (`owner`) و رمز اولیه (فقط بار اول). رمز را یادداشت کنید.
     اگر گمش کردید: `grep OWNER_PASSWORD= ~/chat-poshtibani/.env`
   - چند دستور مفید (همان جدول پایین این صفحه).

اگر `error: 401` یا `404` دیدید، کلید اشتباه است، تاریخش گذشته، یا `poshtibani` در آن انتخاب نشده.
یک کلید جدید بسازید و دستور را دوباره بزنید. اجرای دوباره هیچ چیزی را خراب نمی‌کند.

اگر صفحه همان لحظه باز نشد، چند دقیقه صبر کنید تا رکورد جدید Cloudflare همه‌جا برسد.

## قدم ۵: اولین ورود

1. `https://chat.enetvip.com/admin` را باز کنید و با `owner` و رمزی که نشان داد وارد شوید.
2. منوی **مدیران و امنیت** ← بخش تغییر رمز: رمز فعلی و رمز جدید خودتان را بنویسید و ذخیره کنید.
3. در همان صفحه، برای هر پشتیبان با **حساب جدید** یک حساب جدا بسازید (پشتیبان فقط گفتگوها را
   می‌بیند و جواب می‌دهد).
4. در **راه‌های ارتباطی** شماره و آیدی‌های کلینیک را بنویسید و در **دیتابیس ربات** جواب‌ها را
   اضافه کنید.
5. لینک `https://chat.enetvip.com` را در بیو اینستاگرام بگذارید.

## پشتیبان و انتقال به سرور دیگر (بدون گیت‌هاب)

- **هر روز خودکار:** یک نسخه از اطلاعات در `~/chat-poshtibani/data/backups` (۶۰ روز آخر).
- **پشتیبان کامل:** در پنل مدیریت (فقط مالک) ← **مدیران و امنیت** ← **دانلود پشتیبان کامل**.
  یک فایل zip با همه‌ی کدها و همه‌ی اطلاعات. این فایل اسم و شماره‌ی مراجعه‌کننده‌ها را دارد؛
  جای امن نگهش دارید.
- **انتقال به سرور جدید:** قدم‌به‌قدم داخل فایل `RESTORE.txt` همان zip نوشته شده: فایل را در
  `~/chat-poshtibani` سرور جدید بگذارید و دو دستور بزنید. گیت‌هاب لازم نیست و پورتی هم لازم نیست.

## دستورهای مفید

| کار | دستور |
|---|---|
| به‌روزرسانی از گیت‌هاب | دستور قدم ۴ را دوباره بزنید (اگر کلید تاریخش گذشته، با یک کلید جدید) |
| اجرای دوباره بدون گیت‌هاب | `bash ~/chat-poshtibani/app/deploy/install.sh` |
| دیدن وضعیت | `cd ~/chat-poshtibani && docker compose ps` |
| دیدن خطاها | `cd ~/chat-poshtibani && docker compose logs --tail 60` |
| دیدن وضعیت تونل | `cd ~/chat-poshtibani && docker compose logs --tail 30 tunnel` |
| خاموش کردن موقت (بدون حذف) | `cd ~/chat-poshtibani && docker compose stop` |
| روشن کردن دوباره | `cd ~/chat-poshtibani && docker compose start` |
| عوض کردن آدرس | `CHAT_HOST=chat2.example.com bash ~/chat-poshtibani/app/deploy/install.sh` |

هیچ‌کدام از این دستورها به برنامه‌های دیگر سرور دست نمی‌زند؛ فقط با دو کانتینر چت کار می‌کنند
(`chat-poshtibani` و `chat-poshtibani-tunnel`).

## چه چیزهایی دست نمی‌خورد

- هیچ پورتی روی سرور باز یا گرفته نمی‌شود؛ پورت‌های ۸۰ و ۴۴۳ مال همان برنامه‌های قبلی می‌ماند.
- پوشه‌ها، کانتینرها، سرویس‌ها و تنظیمات دیگر سرور (ربات‌ها، پنل نوبتی، nginx) دست نمی‌خورد.
- نصب‌کننده فقط داخل `~/chat-poshtibani` می‌نویسد، چیزی نصب نمی‌کند و هیچ چیزی را پاک نمی‌کند.
- در Cloudflare فقط رکورد `chat.enetvip.com` عوض می‌شود.

## روش مستقیم (فقط برای سروری که پورت ۴۴۳ آن آزاد است)

روی این سرور لازم نیست. اگر روزی روی سرور دیگری نصب شد که پورت ۴۴۳ آن آزاد است، می‌شود به جای تونل
از روش مستقیم استفاده کرد: در Cloudflare یک رکورد `A` از ساب‌دامین به IP آن سرور با **پروکسی خاموش**
(ابر خاکستری) بسازید و همان دستور قدم ۴ را با `CHAT_MODE=direct` قبل از `bash install.sh` بزنید
(`CHAT_DNS_OVERWRITE=1` را بردارید). نصب‌کننده اول بررسی می‌کند پورت ۴۴۳ آزاد باشد و رکورد به همان
سرور اشاره کند؛ اگر نبود، به چیزی دست نمی‌زند و متوقف می‌شود.
